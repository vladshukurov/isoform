# Isoform — сборка иллюстраций агентом

Это редактор изометрических иллюстраций для сайта Passwork. Иллюстрация — JSON-файл со списком прямоугольных блоков. Пользователь описывает, что нарисовать, а ты пишешь файл `files/<имя>.json`. Открытый редактор (`npm run dev` → http://localhost:8790) сразу показывает изменения, и пользователь доводит сцену руками.

## Через MCP

Если у тебя подключён MCP-сервер isoform — работай его инструментами (`write_scene`, `update_blocks`, `render_preview`, `get_editor_state`), а не файлами: он проверяет сцену до записи и знает, что пользователь выделил. Правила ниже те же.

## Работа

1. Посмотри 2–3 сцены в `templates/` — это готовая серия с сайта. **Не меняй** `templates/`.
2. Напиши или поправь `files/<имя>.json` — руками или рецептом (ниже). Имя — латиница, цифры, дефис. Чужие файлы в `files/` не трогай без просьбы.
3. Запусти `npm run check <имя>` и исправь все ошибки (`✗`): пересечения блоков и формат. Предупреждения (`!`) код не роняют — исправь те, что правда ошибка.
4. Запусти `npm run render <имя>` и **посмотри `previews/<имя>.png`** — без этого не заканчивай. Три кадра в рамке карточки сайта: покой, середина наведения (видны задержки и каскады) и полное наведение. Рядом полезно открыть шаблон: `npm run render templates/cicd` → `previews/templates/cicd.png`. Ищи то, чего не видно в цифрах: читается ли образ, спрятанные соединения, неверный порядок отрисовки, странное движение.
5. Коротко скажи, что построено и что двигается при наведении.

Всё это одной командой: `/illustration <описание>`.

## Рецепты

Когда в сцене повторы, кольца или каскады, проще написать код: `recipes/<имя>.ts` экспортирует по умолчанию сцену (или функцию, возвращающую её), `npm run scene <имя>` проверяет её и пишет `files/<имя>.json`. Примеры — `recipes/example-*.ts`. Помощники из `src/kit.ts`:

- `block(id, x, y, z, w, d, h)`, `plate(id, x, y, z, w, d, толщина = 8)`; `top(блок)` — высота его верха; `GROUND`, `GAP`, `PLATE` экспортируются из кита.
- `onTop(база, id, {w?, d?, h}, зазор = 10)` — по центру базы, на зазор выше; `lidded(id, x, y, размер, высота)` — ящик и крышка толщиной 10 (`<id>-base`, `<id>-lid`).
- `ring(id, r, высота, стенка = 14)` — квадратное кольцо из четырёх стен вокруг начала: `<id>-back-x`, `<id>-back-y`, `<id>-front-y`, `<id>-front-x`. Задние стены рисуются первыми — ставь содержимое между ними и передними.
- `row(id, n, шаг, (смещение, id, i) => блок)` — `n` копий `<id>-<i>`.
- Наведение (в единицах от покоя): `lift(блок, dz, delay?)`, `slide(блок, dx, dy, delay?)`, `grow(блок, {w?, d?, h?}, delay?)` — рост размеров, контур морфится; `retract(блок, '-x' | '+x' | '-y' | '+y' | '-z' | '+z', на, delay?)` — укорачивается с этой стороны, то есть «уходит внутрь» корпуса, не пересекая его (ключ входит в скважину); что висит на этом конце — сдвинь `slide` на столько же; `cascade(блоки, шаг = .04)` — задержки волной.
- `scene({ title, motion, objects })` — порядок отрисовки = порядок массива (вложенные массивы раскрываются). Для одного предмета без переплетений удобнее `sort: true` — сортировка по глубине; для колец, ящиков в корпусе и прочего вложенного — ручной порядок.

## Проверки

- **Ошибки** (`✗`, `npm run check` падает): формат, пересечения в покое и при наведении.
- **Предупреждения** (`!`): блок висит в воздухе (не стоит на верхе другого блока — вплотную или через зазор 10, — не висит под другим блоком и не прикреплён сбоку). Проверяется только покой: при наведении подъём и отрыв деталей — это и есть движение; сцена шире ±250 по X или Y; задержка больше 0.6 с; больше 24 блоков; id не в kebab-case. Все `templates/` проходят без предупреждений.
- `npm run check templates/<имя>` и `npm run render templates/<имя>` работают и для шаблонов.

## Формат

Пример формата (не идея: сейф уже есть в серии — не повторяй его):

```json
{
  "version": 2,
  "title": "Защищённое хранилище",
  "motion": "mechanical",
  "objects": [
    {"id":"safe-plinth","x":-100,"y":-100,"z":14,"w":200,"d":200,"h":8},
    {"id":"safe-body","x":-90,"y":-90,"z":32,"w":180,"d":180,"h":130},
    {"id":"drawer","x":-78,"y":90,"z":120,"w":156,"d":8,"h":32,"hover":{"d":64}},
    {"id":"safe-lid","x":-96,"y":-96,"z":172,"w":192,"d":192,"h":8,"delay":0.08,"hover":{"z":190}}
  ]
}
```

- Блок — прямоугольный брусок: угол `x, y, z` и размеры `w` (вдоль X), `d` (вдоль Y), `h` (вверх). Никаких других форм нет.
- Оси: X уходит на экране вправо-вниз, Y — влево-вниз, Z — вверх. Видны грани `+X` (правая), `+Y` (левая) и верх.
- `title` — подпись для экранных читалок, по-русски.
- **Порядок в `objects` — порядок отрисовки**: от дальних к ближним, каждый следующий перекрывает предыдущие. Обычно достаточно сортировки по `x + y + z`. Если конструкции переплетаются (кольца вокруг фигуры, ящики в корпусе), расставь порядок вручную: сначала задние стенки, потом содержимое, потом передние.
- `id` — осмысленные kebab-case имена (`tank-cap-1`): пользователь видит их в слоях.
- Файл хранится по одному блоку на строку, как в примере.

## Наведение

- `hover` — значения блока в состоянии наведения, только изменившиеся ключи, абсолютные. Изменились только `x/y/z` — блок едет. Изменились размеры — перерисовывается контур: так ящик выдвигается из корпуса.
- `delay` — секунды до начала движения; этим задают волну или каскад (шаг 0.04–0.08).
- `motion`: `"mechanical"` — детали ездят как настоящие механизмы (ящики, тумблеры, крышки); `"layered"` — схема раскрывается слоями и собирается при первом появлении.
- Движение должно быть физически правдоподобным: выдвигается ящик, а не весь шкаф; крышка поднимается вверх; тумблер ездит по своей прорези.

## Правила серии

- **Размеры и сетка**: земля на `z = 14`, сетка 10 единиц. Плиты толщиной 8–16, «парящие» слои с зазором 10 (крышка на 10 выше корпуса). Сцена укладывается примерно в ±200 по X и Y.
- **Без пьедестала**: объект стоит на воображаемой земле, общую подложку под всей сценой не делать. Своё основание у предмета — можно: цоколь у сейфа (storage) — часть сейфа, а не подставка под композицию. Деталь ниже земли тоже допустима как часть предмета (рама `frame-base` в production).
- **Просто и аккуратно**: один ясный образ, обычно до 20 блоков. Без мелких украшений на поверхностях (кнопок, точек, насечек).
- **Не похоже на соседей**: новая сцена не должна повторять силуэт или идею сцен из `templates/`.
- **Без перекрытий, которые путают**: передние детали не должны прятать соединения; блоки не пересекаются (проверяет `npm run check`).
- **Силуэт читается с этого ракурса**: видны только грани `+X`, `+Y` и верх. Тонкая плоская деталь, повёрнутая к зрителю ребром или торцом, теряет форму — ключ перпендикулярно грани читается как Т-образная ручка. Клади такие детали в плоскость XZ или YZ, чтобы их контур лежал на видимой грани, и проверяй по превью.
- Масштаб и вес выравниваются автоматически по площади силуэта, подгонять размеры под карточку не нужно.
